# What was patched in this executable

Generated by `tools/binpatches.py`. Do not edit.

This build of `ArmyMen2.exe` is not what the compiler emitted. Some
conditional branches have been overwritten with unconditional ones --
`74` or `75` replaced by `EB`, same length, nothing else moved. The
tell is the compare left in front of each one, setting flags that are
then never read; no compiler emits that.

**6 such sites**, and every one of them is accounted for
below. Candidates whose jump lands on an instruction that *does* read
the flags are excluded, because that is an ordinary loop back-edge --
without that filter the list is 16 and mostly noise.

| jump | bytes | compare in front | goes to | what it disables | put back |
|---|---|---|---|---|---|
| `0x0040ee9d` | `eb 51` | `test eax, eax` | `0x0040eef0` | copy protection | `75` |
| `0x0042ed4b` | `eb 2e` | `test eax, eax` | `0x0042ed7b` | copy protection | `75` |
| `0x0042f2a9` | `eb 2e` | `test eax, eax` | `0x0042f2d9` | copy protection | `75` |
| `0x0044d303` | `eb 29` | `test eax, eax` | `0x0044d32e` | copy protection | `75` |
| `0x0044d40a` | `eb 25` | `test eax, eax` | `0x0044d431` | copy protection | `75` |
| `0x0044d8fe` | `eb 55` | `cmp esi, ebx` | `0x0044d955` | MULTIPLAYER button | `74` |

## The copy protection

`FindGameCD` (`0x00426B50`) answers non-zero when the ARMYMEN2 CD is
in a drive. Five callers test it and branch past a `MessageBoxA`
saying the CD is required. All five branches are unconditional here,
so none of those dialogs can appear:

| the call | the patched jump |
|---|---|
| `0x0040ee96` | `0x0040ee9d` |
| `0x0042ed44` | `0x0042ed4b` |
| `0x0042f2a2` | `0x0042f2a9` |
| `0x0044d2fc` | `0x0044d303` |
| `0x0044d403` | `0x0044d40a` |

The call itself was left alone -- only the branch on its result --
so `FindGameCD` still runs and still sets what it sets. A faithful
reconstruction calls it and discards the answer, which is what
`src/game/cdcheck.h` does; that header also carries the retail check
as compilable source behind `#ifdef AM2_COPY_PROTECTION`, off by
default.

## The MULTIPLAYER button

`0x0044D110` builds the title menu one button at a time, each the
same shape: allocate `0x78` bytes, compare the result against zero,
skip the button if the allocation failed. Eight of them read
`74 55`. The ninth -- MULTIPLAYER, handler `0x0044D380`, artwork
`03_101_0*_multiplay.bmp` -- reads `EB 55`. Same displacement, one
byte different, and the button is never built. That is the gap on the
title screen between SINGLE PLAYER and OPTIONS.

It can be put back, and doing so is how the reconstructed DirectPlay
code gets exercised at all:

```
AM2_DISPLAY=:99 tools/drive.sh start 25 AM2_MULTIPLAYER=1
```

See `src/inject/restore.c`. It is off by default because anything
enabled there makes this process differ from the binary it is derived
from, which is exactly what `tools/ab.sh` is built to notice.
