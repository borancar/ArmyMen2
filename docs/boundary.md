Generated by `tools/coverage.py`; do not edit. The reconstructed set
is read from the `patch_replace` calls in `src/game/*.cpp`, so it
cannot disagree with what the harness installs.

Only game code is counted. The statically linked MSVC CRT above
0x45c000 reaches plenty of kernel32 itself and is replaced
wholesale by libc rather than function by function.

those functions touch Win32 only through things every Windows program
does -- reading the clock, posting to its own message queue, taking a
mutex, intersecting a rectangle. Reconstructing a 5KB unit-AI routine
to capture one `GetTickCount` would be porting the game, not its edges.
