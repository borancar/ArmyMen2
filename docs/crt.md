## Where the line actually is

The highest function with game evidence is `0x00462600`, and the lowest
with CRT evidence is `0x00464420`. `CRT_START` is set to `0x0045c000`, which
is **26112 bytes too low** -- everything between it and the real frontier
is game code that every count in this project silently drops.

Between the two sits the thunk table: 4 of the image's six
`jmp dword ptr [IAT]` stubs, which the linker parked here rather than
with the code that calls them.

## Is the exclusion safe?

Every count in this project drops everything at or above
`CRT_START`. That is only sound if the game code up there reaches
nothing outside the process, so here is its entire outside contact:

| addr | reaches |
|---|---|
| `0x0045c050` | GetTickCount |
| `0x0045d4b0` | GetTickCount |
| `0x004609d0` | IntersectRect |
| `0x00460ca0` | IntersectRect |
| `0x00460fd0` | IntersectRect |
| `0x004624a0` | COM dispatch |

106 of the 112 game functions above the line touch nothing at all.

The rest is a clock read and some rectangle arithmetic, which this
project calls incidental everywhere else, plus one COM dispatch --
`DrawSeqBar`, which is reconstructed. So the exclusion holds, and it
holds for a measured reason rather than because the constant looks
like a boundary.
